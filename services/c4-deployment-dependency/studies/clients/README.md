to exactly the same files. Every case names its client's directory and a hash
over its files (`client.snapshot`, `client.snapshotSha256`).

## Why the task tracker has no acceptance tests

C3's live run left four model drafted acceptance tests in the project
(`apps/api/src/__tests__/US-1` to `US-4.criteria.test.ts`). Against this code
version two of them fail: they expect the task list to show what the code does
not return that way, and the code is correct (its repository stores what it
creates and deletes what it removes). A control run that fails says nothing
about an update, so every case on the project would have been excluded.

What stays is every test the platform generated without a model: C2's contract
tests, C3's oracle tests, both derived from the API contract, and the web
routes test. They pass at the installed versions, so a failure with an update
applied is the update's. The drafts measure the drafting model, which is C3's
study, not this one.
